# Lessons learned (real incidents)
1. **Docker bypasses the host firewall.** Published container ports ignored the firewall rules. Fix: bind services to the private mesh address only, and test from another device.
2. **Cron has a tiny PATH.** A scheduled agent job failed silently because `claude` was not on cron's PATH. Fix: set PATH in the script; check the log after the first scheduled run.
3. **`pgrep -f` can match its own parent shell.** Three chained scripts waited forever on each other's names while an agent sat idle for hours. Fix: wait on a marker file or a PID.
4. **Unpinned dependencies break in pairs.** A newer media library removed an argument that the transcription package still passed. Fix: hash-pinned requirements with a version cap, and a live test of the real file type.
5. **Free models are fast but need review.** The builder agent's work always went through a second reviewer; the reviewer found real bugs every round (path traversal, race conditions, stale state, rounding).
6. **Scanned books have no text.** A search index looked complete but half the files were images. Fix: report "needs OCR" instead of "indexed", then run OCR in a locked container.
7. **Names that leak.** A public repo build must scrub internal host names, drive IDs and personal names. Fix: an automated scan that fails the build.
8. **Ask, then act, with limits.** Delegated work got a cost cap, a time limit and an undo line each time.
9. **A `chmod` on a mount point does nothing once something is mounted there.** The writable archive mount was reachable by every local user because the drive's own permissions applied. An automated review of the commit found it. Fix: mount inside a root-only parent folder. Lesson: test the guarantee (can a normal user write?), do not trust the intent. Also: do not test a protection by writing to the protected data.
10. **Verify hardware facts with a command, and write them down where they load.** I documented the server as "no GPU" from CPU and memory numbers alone. `nvidia-smi` showed a GPU. The fact was already in a topic file, but not in the short core memory that every session reads. Fix: a rule to verify facts with a command, to update memory as soon as something new is found, and to correct wrong facts everywhere, including public docs.
11. **A GPU can be visible on the host and still unusable, for two different reasons.** First the model server ran on the CPU: inside a long-running container the GPU had failed to initialise (NVML error). Recreating the container fixed that. Then the newest server version crashed on this old card (a segfault while allocating buffers, for every setting I tried). A test matrix in throw-away containers on another port, with the real model mounted read-only, found the newest version that still works (0.10.1; 0.11 and later fail). The image is now pinned, never `latest`. Result: about 20 tokens per second instead of 12, and the whole evaluation suite runs four times faster. Lessons: check inside the container, test upgrades in a copy, pin versions, keep a rollback.
12. **A tool status can say "GPU" while the GPU is gone.** About an hour after a restart the model container lost the GPU again (NVML error). The tool's own status line still said "GPU", but speed fell from 17 to 11 tokens per second and video memory use fell to near zero. The new benchmark reports peak video memory, which caught it. Fix: the daily health note now checks `nvidia-smi` inside the container, and the repair is one line (recreate the container). Lesson: measure the resource, do not trust the label.
13. **A command-line agent can hang on an open input stream.** A scripted call to a coding agent waited forever in a script, but worked in 4 seconds when standard input was closed (`</dev/null`). Fix: close input in every wrapper, add `timeout -k` so a stuck process is killed, and test each wrapper once with a trivial prompt before relying on it.
14. **Isolate a brainstorm team from the main system, and give it one narrow door.** A second team of agents (research, strategy, feasibility, customer test, skeptic) lives in its own folder with its own settings. It cannot read the main project, push to Git or reach the other agents. Its only output is a one-page brief. A `HOLD` file pauses every outside call while the server does heavy work. Each role is a separate named agent that the chair reaches through one script, which accepts six role names only and returns answers through files. Lesson: a narrow, boring interface is easier to secure than a clever one.
